# Development plan: ContactHub

`[ ]` open · `[x]` done.

## 1. Product

- What: a small single-user web app for managing personal contacts (name, date of birth, address,
  phone number, IBAN), persisted in SQLite. Built as a job-interview showcase.
- Users: one anonymous user; no accounts, no roles.
- Must-have in v1:
  - Contact CRUD: list, view, create, edit, delete
  - .NET backend: EF Core (SQLite), FluentValidation for request models and entities, hand-rolled
    CQRS (`ICommandHandler` / `IQueryHandler` + DI, no MediatR), Rich Domain Model (private
    setters, factory and behaviour methods, invariants inside the entity, value objects `Iban`,
    `PhoneNumber`, `Address`)
  - Angular frontend: ngrx Store (actions, reducers, effects, selectors), PrimeNG components
  - One Playwright e2e test: create a contact through the UI and see it in the list
  - Docker Compose for the whole stack, GitHub Actions CI
  - README that maps each reviewer requirement to the code
- Not in v1:
  - Accounts, login, multi-user data
  - Server-side paging, search or sorting
  - Import/export, photos, groups or tags
  - Optimistic concurrency, soft delete, audit history

## 2. Data models and behaviours

### Contact (aggregate root, entity)

- Fields: `Id: Guid` (v7, generated by the factory), `FirstName: string` (trimmed, 1–100),
  `Surname: string` (trimmed, 1–100), `DateOfBirth: DateOnly` (not in the future, not more than
  150 years ago), `Address: Address` (value object, EF complex property), `PhoneNumber:
  PhoneNumber` (value object, stored as normalized string), `Iban: Iban` (value object, stored as
  normalized string, not unique), `CreatedAt: DateTime` (UTC), `UpdatedAt: DateTime` (UTC)
- Relations: none
- Behaviours:
  - All properties have private setters; a private parameterless constructor exists for EF only.
  - `Contact.Create(firstName, surname, dateOfBirth, address, phoneNumber, iban, utcNow)`: anyone;
    trims names, runs `ContactValidator` (FluentValidation `AbstractValidator<Contact>`) and
    throws `DomainValidationException` (property → messages) on failure; sets `CreatedAt` =
    `UpdatedAt` = `utcNow`. `utcNow` comes from an injected `TimeProvider`.
  - `Rename(firstName, surname, utcNow)`, `ChangeDateOfBirth(dateOfBirth, utcNow)`,
    `ChangeAddress(address, utcNow)`, `ChangePhoneNumber(phoneNumber, utcNow)`,
    `ChangeIban(iban, utcNow)`: each re-checks the invariants with `ContactValidator`, throws
    `DomainValidationException` on failure, and bumps `UpdatedAt` only when a value changed.
  - Delete: hard delete of the row; unknown id → 404.
  - List order: `Surname`, then `FirstName` (case-insensitive).
- Created in Task 3; behaviour methods used in Task 4; delete in Task 5

### Address (value object)

- Fields: `Street: string` (1–200), `PostalCode: string` (1–20), `City: string` (1–100),
  `Country: string` (1–100); all trimmed
- Behaviours:
  - `Address.Create(street, postalCode, city, country)`: validates, throws
    `DomainValidationException` with keys `address.street` etc.; immutable; equality by value.
- Created in Task 3

### PhoneNumber (value object)

- Fields: `Value: string` (normalized: optional leading `+`, then 7–15 digits)
- Behaviours:
  - `PhoneNumber.Create(raw)`: strips spaces, `-`, `.`, `(`, `)`; rejects anything else or a wrong
    digit count; `static bool IsValid(raw)` for reuse by request validators; equality by value.
- Created in Task 3

### Iban (value object)

- Fields: `Value: string` (normalized: no spaces, upper case)
- Behaviours:
  - `Iban.Create(raw)`: removes spaces, upper-cases, checks `^[A-Z]{2}[0-9]{2}[A-Z0-9]{11,30}$`
    and the ISO 13616 mod-97 checksum (= 1); `static bool IsValid(raw)`; `ToFormatted()` returns
    groups of four (`DE89 3704 0044 0532 0130 00`); equality by value.
- Created in Task 3

## 5. Assumptions

- No accounts: single anonymous user, so the Identity phase is skipped.
- Database is SQLite via EF Core, per `CLAUDE.md`. **User request:** the file is
  `database/contacthub.db` in the repo root, created on first run; test and e2e files sit beside it.
- **Conflict:** FluentValidation replaces the backend agent's DataAnnotations + `AddValidation()`
  default (Task 3): request validators on commands plus `ContactValidator` for the entity.
- **Conflict:** PrimeNG (Aura theme) is used for all widgets although the frontend agent says "no
  UI library unless `CLAUDE.md` names one"; Tailwind stays for layout via `tailwindcss-primeui`
  (Task 2).
- **Conflict:** ngrx Store/Effects/Entity/Router-Store replace the default signal services and
  `httpResource`; the API service returns `HttpClient` Observables for effects, components read
  state with `selectSignal` (Tasks 3–4).
- **Conflict:** typed Reactive Forms instead of Signal Forms, because PrimeNG inputs are
  `ControlValueAccessor` based (Task 3).
- **Conflict:** one `src/Api` project (per `CLAUDE.md`) split into `Domain/`, `Application/`,
  `Data/`, `Controllers/` folders; entities live in `Domain/`, not `Data/`.
- **User request:** ASP.NET Core controllers (`[ApiController]` classes in
  `src/Api/Controllers/`, scaffolded with `dotnet new webapi --use-controllers`), no Minimal APIs;
  `CLAUDE.md` and the backend agent say the same. Controllers stay thin and only dispatch to CQRS
  handlers (Tasks 1, 3).
- CQRS uses one database and one `DbContext`; queries use `AsNoTracking` projections.
- Address is structured (street, postal code, city, country); the requirement only says "address".
- Phone and IBAN rules are hand-rolled (format + digit count; format + mod-97), no external
  library. IBAN is not unique (joint accounts).
- Ids are `Guid` v7; deletion is a hard delete.
- Playwright was chosen over Cypress; the e2e test runs against the real backend with its own
  SQLite file.
